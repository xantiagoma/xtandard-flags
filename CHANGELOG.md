# Changelog

## v0.2.1

[compare changes](https://github.com/xantiagoma/xtandard-flags/compare/v0.2.0...v0.2.1)

Security fix for the standalone server, the CLI and the Docker image: a mistyped `AUTH_MODE` no longer serves an open panel. Library APIs, storage and the HTTP API are unchanged.

### 🩹 Fixes

- **auth:** reject unknown `AUTH_MODE` instead of serving an open panel ([#23](https://github.com/xantiagoma/xtandard-flags/pull/23)). Any value other than `none` or `basic` (a typo, wrong case) used to fall through to `none`, leaving the admin panel and API unauthenticated. The server now exits with `Unknown AUTH_MODE "x" (expected none or basic)` before it listens. An empty or unset `AUTH_MODE` still means `none`, and now prints the same unauthenticated-panel warning as an explicit `none`.

### Migration

None if `AUTH_MODE` is `none`, `basic` or unset. If a deployment fails to start after upgrading, its `AUTH_MODE` was invalid and the panel was open: set it to `basic` (with credentials) or `none` explicitly.

## v0.2.0

[compare changes](https://github.com/xantiagoma/xtandard-flags/compare/v0.1.11...v0.2.0)

### ⚠️ Migration

- **MySQL (Drizzle storage): run a one-off `ALTER TABLE`.** The `key` column is now `varchar(512) CHARACTER SET utf8mb4 COLLATE utf8mb4_bin`. MySQL's default collation (`utf8mb4_0900_ai_ci`) folds case and accents, so `flags/Acme/…` and `flags/acme/…` were the same row. New tables get the binary collation from the schema; tables created before 0.2.0 need (adjust the length if you set `keyLength`):

  ```sql
  ALTER TABLE flags_kv
    MODIFY `key` varchar(512) CHARACTER SET utf8mb4 COLLATE utf8mb4_bin NOT NULL;
  ```

  If two keys already collided, the table holds only the last write; the `ALTER` doesn't bring the other back. `getKeys` also used `ESCAPE '\'`, a MySQL syntax error, so listing failed on every MySQL call before this release.
- **File storage: keys with uppercase letters get a new file name.** Each key segment is now encoded so it stays distinct on case-insensitive file systems (macOS and Windows defaults): an uppercase letter becomes `^` + the lowercase letter (`Acme` → `^acme`), and characters outside `[a-z0-9._~!@,=+-]` become `%XX`. All-lowercase keys (`flags/default/production/…`) keep their file names, so most trees need nothing. Files written before 0.2.0 are still read and listed, and are replaced by the encoded name on the next write. On a case-insensitive file system such a legacy file can still answer for its lowercase twin until it is rewritten, so if your tree has keys with uppercase letters, re-save them once (read and write back each key from `getKeys("flags/")`).
- **unstorage storage: keys containing `%`, `?`, `\` or `:` are stored under an escaped name** (`%25`, `%3F`, `%5C`, `%3A`), because unstorage cut keys at `?` and turned `\` and `:` into separators. Keys without those characters are unchanged. A key with one of them written before 0.2.0 is not found under its new name (with `?`, `\` or `:` it was stored mangled anyway); write it again.

### 🩹 Fixes

- **storage:** Exact keys and literal prefixes on every backend: `getKeys` on SQLite, libSQL, Postgres and Drizzle keeps only exact `startsWith` matches (SQLite's `LIKE` folds ASCII case); Redis escapes glob characters in `SCAN MATCH`; unstorage lists by plain string prefix. The storage conformance suite now covers case/accent-distinct keys, `? \ :` round-trips and `% _ ! * [ ] ? \ : %25` in prefixes, and runs live against MySQL, Redis and MongoDB in CI ([c9d27ae](https://github.com/xantiagoma/xtandard-flags/commit/c9d27ae))

## v0.1.8

[compare changes](https://github.com/xantiagoma/xtandard-flags/compare/v0.1.7...v0.1.8)

### 🩹 Fixes

- **react:** Scope the embed stylesheet so it can't leak into the host app. `@xtandard/flags/react/styles.css` was a full, unscoped Tailwind v4 build — its preflight resets (`*`, `button`, `h1`, `a`, tables) and generic utilities (`.flex`, `.border`, …) restyled the entire host page, not just `<FlagsDashboard/>`. Every rule is now scoped under the embed's `.xtandard-flags` wrapper (preflight and utilities included), with the design tokens re-homed onto the wrapper and a build guardrail that fails if any rule escapes the scope. Base UI portals (Select/Combobox popups, Dialogs) now render inside the wrapper too, so they stay styled under the scoped stylesheet. The standalone SPA bundle (`dist/ui`) is unchanged.
